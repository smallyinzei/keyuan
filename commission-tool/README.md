# 外贸提成测算与体检

离线单文件网页工具。把季度提成 Excel 拖进浏览器，即可重算部门提成和个人贡献，对比两种口径，拆解差额，体检原表，并导出 Excel。

- **离线**：`release/index.html` 是一个文件，双击即可用（Chrome / Edge / Safari 14+ / Firefox，Mac 与 Windows 通用）。页面带 CSP（`connect-src 'none'`），不会发出任何网络请求，Excel 只在本机浏览器内存中处理，不会上传。
- **技术**：TypeScript + Vite（vite-plugin-singlefile 打成单文件），SheetJS 0.20.3 读 xlsx（含公式文本），ExcelJS 写 xlsx，界面用 Preact。

## 输入要求

- 工作簿内要有成对的「X明细」「X提成计算」工作表，例如“三季度高科明细”“三季度高科提成计算”，X 即公司名。同一文件可以有多家公司。
- 列按**表头文字**定位，不依赖固定行号或列号：
  - 明细：对接人、规格型号、合同数量、含税单价、运费、实际出库、未发数量、订单单号、客户。各月数据块用“高科七月”这类标题行分隔；可选“回款”列（回款数量、回款金额或是否回款）。
  - 明细汇总块：外贸销售均价、内贸销售均价、溢价提成、实发数量；“参考XXX”备注写在同一行。
  - 提成计算：序号（月份）、牌号、出库数量、出库均价（含税/不含税）、变动成本、边际贡献、提成单价档级、提成单价、溢价提成、完成系数、提成合计。
  - 档级表：以 C1 C2 B1 B2 B3 A1 A2 为表头的行。“制度原版”是基准；“N月按实际产量…修正”是当月修正；“未修正”表示沿用原版；“XXXX除外”表示例外型号。
  - 完成率：“销售量/销售额”表头下的“年度计划”“三季度”“三季度完成率”等行（有就读，没有可手填）。
  - 名为“提成计算N月”的隐藏月度表如果存在，会读取其中的变动成本，用来核对复制错误。

## 数据模型

| 模型 | 字段 |
|---|---|
| Order | 公司、月、对接人、型号、合同量、单价（含税单价 − 运费 = 出厂单价）、实发、客户、合同号 |
| Standard | 公司、月、型号、内贸均价、变动成本、档级、单价（由汇总块与提成计算表按型号合并） |
| TierTable | 公司、月（空 = 制度原版）、各档下限 |

## 计算

- 部门提成 = 完成系数 × Σ(数量 × 提成单价) + [完成系数 ×] Σ溢价
- 溢价 = (外贸均价 − 内贸均价) × 10% × 数量
- 个人贡献按 人 × 月 × 型号 汇总，均价用本人订单加权。
- **两种口径同时输出**：主口径按规则配置计算；对照口径在主口径用“合同数量”时取“出库数量”，否则取“合同数量 × 合同均价”。
- **差额拆解**：原表部门提成 → 提成合计按本行重算（修正引用错行）→ 按明细重算汇总（原表口径）→ 补列漏项型号 → 剔除关联公司 → 补录单价 → 切换数量口径 → 切换均价口径 → 完成系数 → Σ个人（均价结构差）。每一步只改一个因素，各步差额相加等于总差额。

## 规则配置（可保存为 JSON）

| 项目 | 取值 |
|---|---|
| 数量口径 `qtyBasis` | `contract` 合同 / `shipped` 出库（默认，原表做法）/ `shippedPaid` 出库且回款 |
| 均价口径 `priceBasis` | `contract` 合同（默认，含未发合同）/ `shipped` 出库 |
| 完成系数 `completion.mode` | `none` / `volume` 按销量 / `amount` 按金额；达成率 ≥80% 取 1，50%–80% 取达成率，<50% 取 0（阈值可改） |
| 溢价需达成目标 `premiumNeedsTarget` | `true` 时溢价也乘完成系数 |
| 人员合并 `personMerge` | `[{from, to}]`，只影响个人贡献 |
| 关联公司剔除 `relatedCustomers` | 客户名列表，按归一后的名称匹配（忽略大小写、标点和 PVT/LTD 等写法差异） |
| 缺单价处理 `missingUnitPrice` | 固定为 `pending`：标记“待补”，禁止按 0 计算；合计注明不含哪些部分 |
| 补录 `supplements` | 补录的提成单价、内贸均价、回款标记 |

规则会自动保存在本机浏览器（localStorage）。也可以导出 JSON 存档，或发给同事导入。

## 体检项目

每条问题都给出：严重度、位置（工作表!单元格）、原值、应为、影响金额。影响金额按原表口径（出库数量 × 合同均价）估算对部门提成的影响，正数表示应增加。

1. 重算汇总均价、实发数量，与表内值比对（识别两型号实发互换）
2. 未发 = 合同 − 实发；实发不得大于合同
3. 提成计算表各行引用的是否为同一型号、同一月份（跨表引用与本表引用错行），并给出更正后的公式
4. 档级与档级表一致（按当月修正表 / 制度原版 / 例外型号）
5. 同档单价一致
6. “参考某型号”备注与数值一致
7. 档级边界重叠、空档、格式问题
8. 有实发但未进提成表的型号
9. 缺单价（主口径、对照口径分别标注）
10. 客户名归一（同一客户的不同写法）
11. 同一合同号客户一致
12. 变动成本：同月不同型号成本相同；有月度成本表时核对公式基数，识别复制错误
13. 其他：公式重算（提成合计、不含税均价、边际贡献、溢价）、手填数值、合同号月份、口径混用、完成率缺失、疑似关联公司

工具只自动采用可由明细数据证明的修正：引用错行、汇总数量/均价、漏列型号。档级、同档单价、参考备注、变动成本这类问题需要业务确认，只报告影响，不改动计算。“修改说明”中会逐条区分“重算已采用”“待确认（未采用）”和“待补”。

## 导出

- **个人贡献表**：沿用原格式，列为 合同均价 / 出库数量 / 内贸销售均价 / 部门提成单价 / 出库量提成 / 溢价提成 / 小计 / 备注。主口径、对照口径各一张，另附个人汇总和口径对比。单元格保留公式。
- **体检报告**：问题清单（带筛选）和按类别的汇总。
- **修改说明**：逐条修改说明、部门提成对账（瀑布）、待补事项、本次规则配置。另有纯文字版，可直接复制。

## 开发

```bash
npm install
npm test            # 单元测试（合成数据，不含任何真实业务数据）
npm run build       # 类型检查 + 打包，输出 dist/index.html 并复制到 release/index.html
npm run test:e2e    # 需能加载 Playwright：项目内安装，或设置 PLAYWRIGHT_MODULE 指向 playwright 目录
```

仓库中不保存任何真实提成数据。测试用的工作簿由 `tests/fixture.ts` 按原表版式合成，数据全部是虚构的。
